# Android app end to end, streaming path, 2026-09-14

The app on an Android emulator against the real application — its own lifespan and orchestrator,
PostgreSQL, the configured speech service and model — with only the telephone network simulated by
`tests/support/simulated_twilio.py`, as [`live-rehearsal.md`](live-rehearsal.md) runs it. Where the
[emulator smoke test](emulator-smoke-2026-09-13.md) covered the handset path, this run covers what a
user of a forwarding deployment sees: setup with call forwarding, Home, Activity, a summary and its
transcript, Hindi calls, a live escalation, privacy and deleting. Push notifications and iOS are
later phases and were not run.

## Setup

| Item | Value |
| --- | --- |
| Emulator | Pixel 8 image, Android 16, `arm64-v8a` debug build, JS from a Metro on a spare port |
| Backend | `test/app-e2e`, on loopback on a spare port, a throwaway database dropped afterwards |
| Providers | simulated streaming telephony, the configured speech service and model, `OTP_PROVIDER=mock` |
| Languages | `SPEECH_LANGUAGES=en,hi`, a catalogue with one Hindi voice |
| Numbers | the user `<user line>` and one caller, both in `+1 202 555 01xx`; the forwarding number the simulator's |

A small driver kept the application running and placed calls on demand: the caller's lines spoken
by the speech service's text-to-speech into the media stream at a phone line's pace, the user's leg
left ringing until told to answer, and the caller hanging up when told to. The application was
restarted three times to pick up fixes, each time with a new database, so the user signed in and set
up again.

## Defects fixed on this branch

1. **Home claimed the assistant could not talk to callers** (`c86bfab`). Home chose its
   screening-only state whenever the phone held the screening role, without asking whether calls
   also reach the assistant forwarded. The profile's `call_forwarding` now decides it.
2. **The agent hung up on the assistant's last sentence** (`9f4dd5e`). A call the agent's judgement
   ended was terminated the moment it asked, while the assistant was usually still speaking: the
   service's record for the first Hindi call shows the last reply `interrupted` by the disconnect,
   and that reply, queued behind its audio, never reached the transcript. The run now waits, bounded
   by `goodbye` (10 s), for the assistant to be quiet for `goodbye_pause` (1 s), and records any line
   still in its inbox before storing the call.
3. **Two locales** (`ce759d9`). `/v1/me` read and wrote a locale column on the user row; calls,
   summaries and notifications used the preferences' locale, and so did nothing else. The escalation
   screen read the row, so a Hindi user's notification and the screen it opened disagreed. Both now
   use the preferences' locale. The column is still written and no longer read; removing it needs a
   migration.
4. **Details under machine keys** (`9df5ecb`). The summary screen printed each detail's label as the
   backend sends it (`commitment_declined`). The test backend used "Left at", a label the real one
   never sends. Each kind now has words; an unknown one is shown as sent.
5. **A live escalation screen never moved on** (`c7da736`). It read the escalation once; while live
   it now reads it again every five seconds, without a spinner, and turns to the finished state.

## Open findings, not changed

1. **A resolved call can end on the assistant's question.** In 4b the assistant's last line asked
   the courier whether they wanted to be told where to leave the parcel, and the agent's judgement
   ended the call as resolved straight after; the fix above lets the question be heard, not
   answered. The speech agent and the judging agent do not coordinate the ending; a prompt change
   goes through `scripts/agent_evaluation.py`.
2. **The same message taken again on every look.** A call that rang the user for 150 s stored 12
   near-identical `message` details, one for each judgement that took a message.
3. **Handset reports are dropped on a forwarding deployment.** An Android phone on such a deployment
   still screens calls and reports them; `POST /v1/calls/reports` accepts the reports, but only the
   handset transport turns reports into calls, so a call the phone turned away never appears in
   history. Whether the handset should screen at all there is a product decision.
4. **Summary quality.** One Hindi summary kept "courier company से बोल रहा हूँ" as a `name`; one
   English headline said "you could not reach you".
5. **The escalation screen has no joined state.** While the user is on the call it still reads
   "Needs you" and "Answer your phone to join"; the designs draw only live and finished.

## Limitations

- **Host load.** Load averages reached 240. uiautomator dumps took 5–70 s and failed while Home's
  needs-you timer ticked every second; system dialogs ("isn't responding") had to be waited out.
- **The emulator was shared.** Part-way through another session restarted `emulator-5554` and
  drove the same app from its own Metro and backend; an app built here loaded that Metro's bundle
  through the shared `adb reverse`. The run moved to a second AVD of the same image on another
  port with the dev server host set explicitly, and that AVD was deleted afterwards.
- **Ring length.** The product rings the user for 30 s; reading the ringing state took longer than
  that, twice, and both rings ran out unread. The driver then rang for 150 s by replacing the ring
  bound in its own process.
- **Call budget.** Eight calls used the speech service against a budget of about six, two of them
  lost to the timing above, so the answered escalation (5c) and the hang-up during the ring (6) were
  not run on the emulator. Both paths are covered by `tests/e2e/test_escalation.py` and the unit
  tests in `tests/unit/application/orchestration/`.
- **FLAG_SECURE.** Home with calls, Activity, the summary, the transcript and the escalation screen
  are kept out of screenshots, so Devanagari was checked as text from uiautomator, not as rendered
  glyphs.
- **No push.** Escalations were delivered as `no_devices`; the app was opened to see them.
